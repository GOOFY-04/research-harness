保形预测的原审稿把覆盖率变化方向说反了。独立复跑得到：提出方法覆盖率 **0.84**、
平均宽度 **2.934**；固定基线为 **0.81**、**2.8824**。入口当时只导出了宽度比较。
全部漂移事件还都发生在最终评测片段之前，这限制了对“漂移时适应能力”的判断。
本轮补充了完整指标输出和负结果分类的提示，但没有改写旧审稿来制造通过。

稳健均值方法的等权平均 MSE 为 **0.06693**，固定截尾基线为 **0.21743**，中位数基线
为 **0.02720**。总体平均值掩盖了场景差异：

| 场景 | 提出方法 − 固定基线的配对 MSE 差 | 配对标准误 |
| --- | ---: | ---: |
| 干净高斯 | 0.001506 | 0.000644 |
| 5% 对称污染 | 0.002882 | 0.000307 |
| 5% 单侧正污染 | 0 | 0 |
| 15% 对称污染 | 0.005323 | 0.001884 |
| 15% 单侧正污染 | -0.762186 | 0.025598 |

每行使用同一场景的 50 对测试结果。MSE 越低越好；正差值表示提出方法较差。
这些配对统计来自独立复跑审计，未插入原会话的执行证据，也不代表新的独立重复实验。
原审稿把部分“假设没有成立”列为 validity 缺陷，并使用了原报告没有提供依据的显著性
表述；这暴露出模型审稿的分类和论证可靠性仍需验证。

## 离线复跑

```powershell
.\.venv\Scripts\python.exe -m experiments.replay_live_cases --output experiments/results/live_replay_20260922.json
```

命令校验保存代码的文本哈希、运行原入口、比较记录指标并计算额外审计结果，无模型
请求或数据下载。材料见 [案例说明](../experiments/live_cases/README.md)、
[原始会话摘要与源码哈希](../experiments/live_cases/manifest.json) 和
[复跑结果](../experiments/results/live_replay_20260922.json)。源码按原样保存，包括其缺陷。

## 距离结束验收的缺口

1. 实验契约还需明确指标含义、方向、评测片段及配对统计，防止数值能复现但问题没测对。
2. 原始逐样本证据需要单独落盘并纳入哈希清单；日志尾部不能代替完整数据归档。
3. 生成元数据仍可能包含伪依赖，例如本次的字面量 `None`；科研结果复跑通过不等于交付说明正确。
4. 必须用可信负结果测试审稿分类，避免把方法失败判为实验无效，也避免无依据的显著性结论。
5. 尚未完成两次连续的干净环境完整科研验收，更没有据此证明算法原创性或整体研究质量优于开源项目。

本轮能够支持的差异化证据是：真实失败被保留、恢复没有重跑已验证文件、指标采集漏洞
被发现并修复、科研验收没有因程序跑完而自动放行。原创性边界见
[ORIGINALITY.md](ORIGINALITY.md)。
